# DebitMyData skill

An agent skill that lets AI agents use DebitMyData services, starting with DID registration
through the [DebitMyData Agent Gateway](https://github.com/DebitMyData-PoW/agent-gateway).
It follows the open SKILL.md format: Codex first, and any other agent that supports skills.

## Development status

Milestone 2 implements a staging-only Python CLI with 89 passing offline tests and one
completed, verified DMD regtest registration on Gateway v0.11.0. The approved run resumed
after a timestamp precision fix, retaining the same key, quote and payment. Implementation
review and M3 behavioral validation/handover remain pending. Further live tests require a
new agreed budget; the completed test is not permission for repeated registrations.

## Version 1: DID registration on staging

Staging only until real payments are enabled. Staging runs on a private DMD test chain whose
coins have no value.

| Step | Call |
| --- | --- |
| 1. Create the agent key | Ed25519, generated by the agent itself |
| 2. Get a quote | `POST /v1/dids/registration-quotes` |
| 3. Pay the quote | staging: `POST /v1/staging/test-payments` |
| 4. Wait for the payment | `GET /v1/payments/{payment_intent_id}` until `status` is `settled` |
| 5. Get a controller challenge | `POST /v1/dids/registrations/{registration_intent_id}/controller-challenges` |
| 6. Sign it and send the proof | `POST /v1/dids/registrations/{registration_intent_id}/controller-proofs` |
| 7. Get the DID | `POST /v1/dids/registrations` |
| 8. Check it | open `did_document_url`; check the credential against `/.well-known/did.json` |

- Quote body: `display_name`, `participant_type` (`autonomous_agent`), `controller_public_key`,
  `preferred_payment_option` (`dmd_pow_native`).
- Time limits: pay within 15 minutes of the quote; send the proof within 5 minutes of the
  challenge.
- Public key: `ed25519:` + multibase base58btc of `0xed01` + the 32-byte key
  (`ed25519:z6Mk...`).
- Signature: Ed25519 over the challenge `message` string (UTF-8, exactly as received),
  base64url without padding.
- Discovery: `GET /v1/discovery` and `GET /v1/payment-options`.

## Rules

- The agent creates its own key and only ever sends the public key.
  `POST /v1/staging/test-agent-keys` is for people trying the docs page, not for the skill.
- `POST /v1/staging/test-payments` is the only staging shortcut. In production the agent pays
  from its own wallet.
- Never commit keys, wallets or `.env` files.
- Test coins are limited: no load tests or registration loops against staging. The single
  maintainer-approved smoke test used three of its six allowed payment-status checks;
  see the validation report. That approval does not authorize further registrations.
